# Rex public surface, October 2026

**TL;DR.** October 2026 recon of Rex's public macOS test against phux.
Persistence, splits, input, program status, and both macOS clients are
on main; remote is still an explicit dial. The workspace slice
(`0f0e0813e`, `c6b2ff20b`, `e72b0c922`) and the inbound decode alias
(`68bb7dc57`) are on main. Live Cockpit acceptance against a second
host stays blocked. OS login and a Windows client stay out.

This note is the October public surface, not a rewrite of the September
demo reconstruction. That map and the beads it produced stay in
[`2026-09-09-superlogical-demo/`](./2026-09-09-superlogical-demo/README.md).
Claims here were checked against `origin/main` at `15124c2c6`.
The first draft used `bd685d46e`, then `0f0e0813e` (#1108). A later
commit is cited only when it is an ancestor of `15124c2c6`.

## October 2026 public surface

Rex is the terminal itself. The 5 October 2026 announcement calls it a
drop-in replacement for the terminal you use today, not a multiplexer
you run inside one
([public testing](https://www.superlogical.com/updates/public-testing-beginning)).
The 8 October briefing says the same thing: you open the app and you
are in a terminal
([Bitdoze](https://www.bitdoze.com/superlogical-rex/)).

Sessions persist. The server keeps a session running whether or not a
client is looking at it
([CLI taxonomy](https://www.superlogical.com/rex/docs/automate/cli)).
A session holds windows (tabs); a window holds blocks; today a block is
a terminal. Closing the app does not end the session.

Remote is not a separate mode. The macOS app self-hosts a Rex server
and connects to other Rex servers through that same app (5 October
announcement). The CLI selects another server with `-S` / `--server`
on the same commands, by host label or address, rather than a remote
subcommand
([CLI targets](https://www.superlogical.com/rex/docs/automate/cli)).
The September demo's stated rule, which the 8 October briefing repeats,
is that what works locally should work remotely
([SPEC.md](./2026-09-09-superlogical-demo/SPEC.md), narration
04:31–04:47; [Bitdoze](https://www.bitdoze.com/superlogical-rex/)).
That is a product-surface claim. The same demos also show a real OS
login (`who`, a login shell). That part is out of scope here; see
[ADR-blocked](#adr-blocked).

Program activity is a published protocol, not only a demo. OSC 7501
(revision 0.3, 7 October 2026) lets a program report `idle`, `working`,
`blocked`, `done`, or `error`. Rex shows that in the session picker and
on unfocused tab headers, and Lua can hear
`terminal.program_status_changed`
([Program Status Protocol](https://www.superlogical.com/rex/docs/build/program-status)).
The announcement lists "program activity status" next to persistence
and remote connections.

The CLI can create sessions, run commands, split, move focus, and
inject input. Mitchell Hashimoto's 14 September 2026 CLI demo says you
can create sessions, run commands, make splits, move things, change
focus, and simulate key and mouse input, and that the changes show up
on connected clients immediately
([post](https://x.com/mitchellh/status/2099622049325232505);
[YouTube](https://www.youtube.com/watch?v=9fcfDF8SBnc)). The public
docs name the commands: `rex new`, `rex run`, `rex split` (with
`--focus=false`), `rex send`, and `rex send-key`
([shell scripting](https://www.superlogical.com/rex/docs/automate/shell-scripting)).

A streaming event feed is `rex events`. It prints session, window,
block, and terminal events until interrupted; `-s` follows one session
and `--json` is one JSON object per line
([events](https://www.superlogical.com/rex/docs/reference/events),
[shell scripting](https://www.superlogical.com/rex/docs/automate/shell-scripting)).
Terminal events include exit, directory, title, bell, foreground
process, and program status.

The macOS app is in public testing as of 5 October 2026, by mailing-list
invite. Linux and Windows servers, and iOS, Linux, and Windows clients,
exist internally at varying readiness and are not in that public test
(the announcement, and the
[installation page](https://www.superlogical.com/rex/docs)). Rex is
described as free, with no account, and self-hosted. A commercialization
plan is promised before the stable release and is said not to charge
for the clients or servers themselves.

## What phux already has

Checked on `origin/main` at `bd685d46e`. "On main" means the path below
is in that tree.

| Rex behavior | On main | Where |
|---|---|---|
| Persistent sessions | Yes. Detach drops clients; the server keeps the sessions. Quit of the desktop app detaches and does not kill server-owned shells. | [`crates/phux/src/commands/detach.rs`](../crates/phux/src/commands/detach.rs); [`docs/adr/0003-server-process-model.md`](../docs/adr/0003-server-process-model.md); [`clients/desktop/README.md`](../clients/desktop/README.md). `phux new --empty` keeps a session with no window ([`commands/mod.rs`](../crates/phux/src/commands/mod.rs) `New`, ADR-0105). Cockpit connects to registry hosts over a QUIC or WSS tunnel ([`clients/cockpit/docs/REMOTE_HOSTS.md`](../clients/cockpit/docs/REMOTE_HOSTS.md), [`startup.zig`](../clients/cockpit/src/cockpit/startup.zig)). |

## ADR-blocked

OS-login, PAM, and utmp sessions are not implemented and must not be.
ADR-0003 is one server per OS user: panes are children of that user's
daemon. ADR-0106 says the server never switches users, `root@host`
reaches root's own server, and PAM, utmp, and loginctl stay with the
service manager. ADR-0073 only adds a login shell (`-l` / `--login`)
when the server was started by its own service unit. Rex's demonstrated
system login (a session that shows up in `who`, with principal-to-user
mapping) is the model those ADRs refuse. The September map already
marks F06, F07, and F14 out of scope for that reason.

A Windows client is not implemented and must not be added from this
recon. [`docs/INSTALL.md`](../docs/INSTALL.md) says Windows is not
supported and is not on the near roadmap. ADR-0139 limits the desktop's
first release target to Apple-silicon macOS. No Windows tree exists
under `clients/`.
