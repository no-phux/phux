# 0164 — Pair links name the host's MagicDNS name

**TL;DR.** On a tailnet with MagicDNS enabled, `phux pair` names the host by
its MagicDNS name (`studio.tail9a8b.ts.net`) in both the `url` and `quic`
endpoints of the connect link, wherever the endpoint's address is one of the
node's own tailnet addresses. Addresses stay the fallback. The link shape does
not change, and pinning makes the certificate's names irrelevant to phux
clients, so no existing pairing breaks.

Status: Accepted
Date: 2026-10-13
Builds on: [ADR-0141](./0141-pair-mints-only-against-a-live-listener.md),
[ADR-0091](./0091-certificate-names-the-advertised-address.md)

## Context

[ADR-0141](./0141-pair-mints-only-against-a-live-listener.md) has the link name
the address the listener is bound to: for the auto-bound overlay listener, a
`100.x` tailnet address. That address belongs to the tailnet, not the host. A
re-authenticated or re-added node can come back with another one. The phone
keeps the link's endpoints, so its saved server then dials an address that is
gone, and the user has to pair again. The node's MagicDNS name survives that
reassignment, and every tailnet client with MagicDNS on resolves it.

## Decision

1. **Detection.** `phux_config::overlay::detect_magic_dns` runs the same CLI
   as address detection (`tailscale`, or `PHUX_TAILSCALE`) as
   `status --json`, under the same two-second deadline. It returns
   `Self.DNSName` with the trailing dot trimmed, and `Self.TailscaleIPs`. It
   returns nothing when `CurrentTailnet.MagicDNSEnabled` is not true, when the
   name is not a plain dotted DNS name, or when `PHUX_OVERLAY_ADDRS` is set.
2. **Substitution.** A link endpoint resolved from a bound listener (its own
   address, or the overlay address chosen for a wildcard bind) is written as
   `NAME:PORT` when that address is one of `Self.TailscaleIPs`. A bind on any
   other address keeps the address. `--host` is the operator's claim and
   disables substitution for the run.
3. **Certificates.** The name joins the names `phux pair` advertises, so a
   certificate generated by that run claims it. An existing certificate is
   never widened (ADR-0091). Unlike other advertised names, an uncovered
   MagicDNS name draws no warning.
4. **No contract change.** The link keeps its fields and their order. `url`
   and `quic` already allow a DNS host, and the CLI, the iOS parser, and the
   Android parser all accept `quic://NAME:PORT`.

## Why

Every phux client, the phone included through the shared Rust runtime,
verifies the server by pin. The `phux-dial` verifier compares the leaf SHA-256
(`fp`) or the CA the chain verifies under (`ca`, ADR-0153) and never reads the
server name. The name only selects what is resolved and what SNI is sent. The
server presents one certificate whatever the SNI. Naming the host by a DNS name
therefore needs no new certificate and changes no fingerprint. The name moves
with the host.

The warning is skipped because the server's own listener provisions most
certificates at its first start, from its bind address alone, with no
MagicDNS lookup on the startup path. Warning would put the ADR-0091 remedy,
delete the certificate and re-pair every device, beside almost every link,
for a name no phux client checks.

## Tradeoffs

- A client must resolve MagicDNS. A device with Tailscale DNS turned off
  (`--accept-dns=false`, or the app's "Use Tailscale DNS" off) cannot dial a
  link that names the host. `PHUX_OVERLAY_ADDRS` or `--host` keeps a link on
  addresses.
- `phux pair` pays a second CLI call. The two-second deadline still bounds it.
- A browser or `curl --cacert` dialing the name fails name validation against
  a certificate generated before this decision, and `phux pair` does not say
  so.
- Only Tailscale gets a name. Other overlays keep addresses.

## Alternatives

**Leave links on addresses.** Every address reassignment costs a re-pair on
every device, which is the problem this decision exists to remove.

**Name the host only in `quic`.** Older apps dial `url`, and a link whose two
legs name the host differently is harder to reason about. Both legs use the
name.

**Widen existing certificates to claim the name.** It rotates the fingerprint
every paired device pins. ADR-0091 rejected it, and pinning makes it
unnecessary.
